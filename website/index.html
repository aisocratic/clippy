You know this one.

You kick off a long agent task, switch to Slack, and twenty minutes later discover it's been sitting at a permission prompt the whole time.

Clippy fixes that: floating, draggable pixel buddies — always on top, on every Space — that know the live state of every session. A buddy pops up only when its session actually wants you, where the session lives (perched on that terminal or editor window), and it doesn't give up: it re-nudges every 90 seconds until you respond, snooze, or dismiss.

While the agent works, Clippy stays hidden. Answer the card — or type a new prompt in the terminal — and it slips away again.

What the little guys can do

🛂 Answer it right there

Permission requests become a card with the exact command or edit: Allow, Deny with a reason Claude sees, or hand it back to the terminal. Plans get Approve / Revise — your note sends Claude back to planning. Multiple-choice questions become buttons; your pick is fed straight back, so the terminal picker never appears.

✅ Review the turn

When Claude finishes, a review card leads with what it actually said it did. Looks good lets it stop; type what's missing and Send feedback — Claude keeps working with your note, no terminal round-trip.

🪟 Perches on the session's window

A buddy appears on the top-right corner of the window its session runs in — Terminal, iTerm2, VS Code, Cursor, Ghostty and friends — and follows it as you move it. Every card has a go to terminal ↗ button that raises the right window.

⚙ Live activity line

A small line under each buddy shows what that session is doing right now: ⚙ Running: npm test, ✏ Editing server.js, ✓ done — your turn, ⚠ Bash failed. Ambient — it never pops the window.

📊 Token usage, honest bars

Click a buddy for the session panel: context left in this conversation over a progress bar, plus bars for the rolling 5-hour block, the week, and Opus's own week. Tell Clippy your plan (Pro, Max 5×, Max 20×, or Custom) and they become real allowance bars.

⌨ Chat straight to the agent

Type the next prompt into the panel and hit Enter — Clippy raises that session's terminal and types it in for you. Or go further with Drive mode: Clippy launches a headless session via the Claude Agent SDK, with a streamed transcript, prompts and cards all in the GUI.

🎭 One buddy per project

Every session gets its own buddy with a name plate and a colour derived from the project name — the same repo always gets the same face, and parallel agents rarely match. Hand-pick a character per project when you care.

🧪 A sandbox for every state

Dev tooling included: npm run sandbox renders every UI state on one scrolling page (no Electron), a browser test bench replays a full scripted show run, and npm run mock-session drives the real app through a realistic session — no Claude Code needed.

How it works

Claude Code's hooks fire shell commands on lifecycle events — and a hook's stdout can answer the event. The installer registers nine tiny curl hooks that POST each event to the app on localhost. Two of them are interactive: their HTTP response is the hook's decision.

Claude Code session(s)
   │  hooks: PermissionRequest / Stop / Pre+PostToolUse / Notification / Session*
   ▼  curl POST → http://127.0.0.1:43117/hook/<event>   (response = hook decision)
Clippy app (Electron)
   ├─ session tracker: who's working, waiting, blocked — and what they're doing now
   ├─ decision broker: holds interactive hooks open until you click (or timeout)
   ├─ one floating Clippy per session (hidden until it needs you): name plate,
   │    activity line, approval/plan/question/review cards, snooze
   ├─ native macOS notifications (clickable)
   └─ menu bar item 📎 with a count of sessions waiting on you

The activity hooks match only meaningful tools — Read, Grep and friends never even fire a hook, so there's no latency and no spam on the noisy read-only stuff.

Built to be easy

  • Nothing is ever auto-approved. If you don't answer in time (60s for approvals, 30s for reviews), Clippy answers “no decision” and the normal terminal prompt takes over.
  • Only real prompts. PermissionRequest fires only when Claude Code would actually show a permission prompt — allowlisted commands run at full speed, untouched.
  • Localhost only. The hook server binds to 127.0.0.1 and accepts nothing but hook event JSON. Nothing is exposed to the network; no session content leaves your machine.
  • App off = normal Claude Code. When Clippy isn't running the hooks fail instantly (--connect-timeout 1 … || true) and Claude Code behaves exactly as if Clippy didn't exist.
  • Your call, per behaviour. Permission requests, questions and finish-reviews each have an on/off switch in Quick settings, and the toggles persist. npm run hooks:uninstall removes only Clippy's own entries.

Questions people ask

Does it work with Codex, OpenCode, or other agents?

Today Clippy speaks Claude Code's hooks — that's the only Claude-specific piece. The session tracker, cards, and buddies don't care who's on the other end: any agent that can POST lifecycle events to localhost could drive them. If your agent has a hook system, an adapter is a small script, and issues/PRs are welcome.

Will it approve things on its own?

Never. Clippy only relays your clicks. Unanswered cards time out to “no decision” and the normal terminal prompt takes over, exactly as if Clippy weren't there.

Does it cost anything to run?

Watch mode is free — it's your normal terminal sessions, observed via hooks. Only the optional Drive mode (Clippy-owned headless sessions via the Agent SDK) consumes credit, and it's a separate opt-in install.

Why does macOS ask for Accessibility permission?

Perching on a terminal window, raising it, and typing a prompt into it are all macOS Accessibility features. Decline and Clippy still works — buddies just sit in the screen corner instead of riding your windows.

How do I get rid of it?

npm run hooks:uninstall removes exactly the hook entries Clippy added (they're tagged), quit from the menu bar, delete the folder. Done — no daemons, no leftovers.
